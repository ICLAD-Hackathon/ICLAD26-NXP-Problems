Multi-Domain Crypto SoC

HARD iverilog TileLink-UL · AXI4-Lite · APB · AES-128 · DMA Architecture reference -- diagrams, signal flows, and minimal spec

Problem Statement

Study the architecture diagrams below to understand this multi-domain SoC: a 4×3 TileLink NoC mesh, four AES-128 engines, two DMA channels, an AXI-Lite crossbar, an APB peripheral cluster, dual IRQ aggregators, an async mailbox, and performance counters. From the structure shown, infer the configuration of every block, generate the corresponding RTL, and stitch the complete SoC so that the provided testbench passes. All numeric parameters (widths, depths, counts) are for you to determine from the diagrams.

01

SoC Topology

4×3 TileLink Mesh + CPU Fabric
Reading the diagram: Column x increases left-to-right (x=0..3). Row y increases top-to-bottom (y=0..2). Node (0,0) is top-left. The CPU (with inline xbar) and both DMA engines are placed on the left side -- each connected by a short direct arrow into their column-0 inject node. No arrow crosses the mesh. AES engines occupy nodes (2,0), (2,1), (3,0), (3,1). Each horizontal gap is a bidirectional TileLink bus (East port p2 of one router meets West port p3 of its eastern neighbour). Each vertical gap is a bidirectional N-S TileLink bus (p0 North / p1 South).
Link wiring principle: Each mesh link is a single shared TileLink bus. The East port (p2) of one router and the West port (p3) of its eastern neighbour are the same physical wires -- they must be connected together, not driven independently. The same applies to the North (p0) and South (p1) ports of vertically adjacent routers.

Packet Flow: XY Routing Walkthrough

Step-by-step example
How XY routing works: The router inspects addr[31:28] = dest_x and addr[27:24] = dest_y. First it hops East or West until dest_x matches, then it hops North or South until dest_y matches, then it delivers locally. The diagram below shows a CPU write to address 0x1100_xxxx (dest_x=1, dest_y=1, target = node (1,1)).
03

CPU-Side Fabric

AXI Crossbar + APB Cluster + SoC Config Registers
The CPU AXI4-Lite master connects to a 2M×3S AXI-Lite crossbar. Master 0 is the CPU; Master 1 is the DMA config bus (held idle unless actively programming a DMA engine). The three slave decode regions are shown below. Slave 0 spans the entire NoC address space and connects to the TileLink NI at node (0,0). Slave 1 routes to the APB bridge and peripheral cluster. Slave 2 is the SoC configuration register block (16 x 32-bit registers).
04

Reset Synchronizer

FF sync chain
Generates sys_rst_n: asserts asynchronously when por_n goes low, deasserts synchronously after passing through the FF chain. Count the FF boxes to determine the synchronizer depth. The chain has 4 flip-flops, so sys_rst_n goes high 4 clock cycles after por_n is reasserted.
05

TileLink-UL Router

XY routing -- 5 ports
Each router exposes 5 ports: p0=North, p1=South, p2=East, p3=West, and a Local inject port (p4, connects to its node's NI or DMA engine). Routing is XY-first. Address bits [31:28]=dest_x, [27:24]=dest_y. Determine port count and bus widths from the interface shown. The inject port exists on all nodes; for DMA-inject nodes (0,1) and (0,2) the DMA master drives this port directly. For all other nodes the NI drives it.
Port direction convention: p0 (North) connects toward the node with higher y index (y+1); p1 (South) connects toward the node with lower y index (y-1). The router's XY routing logic likewise treats dest_y > NODE_Y as "go North" and dest_y < NODE_Y as "go South". Boundary ports (no neighbour) must be tied to zero.
D-channel limitation: D-channel responses (read data / write ack) are returned only to the local inject port of the node where the transaction was accepted. D-channel packets do not propagate back across multiple hops. As a consequence, AXI reads issued to remote nodes will not return rvalid to the originating CPU; only writes need to be verified for correctness.
06

TileLink NI — AXI4-Lite to TL-UL Bridge

bridge
One NI per node. The NI is an AXI4-Lite slave on one side and a TL-UL master on the other. AXI and TL-UL bus widths match; determine them from the signals shown. The NI's TL-A output connects to the router's inject port. The TL-D response (read data or write ack) must be latched into a register. bvalid and rvalid must remain asserted until the AXI master accepts (bready/rready), which requires a holding register since tl_d_valid is only a one-cycle pulse.
07

AXI-Lite SRAM

memory slave
One AXI4-Lite SRAM per node. The router drives its AXI ports directly (no NI on the local path). Determine depth, data width, and address width from the interface shown and the address map. The address bus is sized to address every word of the memory.
Width note: The SRAM data width is 64 bits (wstrb[7:0]). The CPU AXI master uses a 32-bit data bus (cpu_wstrb[3:0]); the Network Interface translates this to a 64-bit SRAM write by zero-extending wstrb and placing the 32-bit data in the correct half-word lane of the 64-bit word.
08

AES-128 Engines

aes0@(3,0)   aes1@(3,1)   aes2@(2,0)   aes3@(2,1)
Four AES-128 engines, all using ip_type: aes128. Each takes a 128-bit key and 128-bit plaintext, outputs 128-bit ciphertext. The done output is a single-cycle pulse after 10 rounds; busy is high during computation. Done signals feed the irq_crypto aggregator as src[0..3]. Important: The AES engines are standalone instances, not connected to the router's local AXI port. Every node, including AES nodes at (2,0), (2,1), (3,0), (3,1), still has a regular axi_lite_sram as u_sram_XY on its router local port. The AES engines sit beside the SRAMs, not in place of them.
09

DMA Engine

memory-to-memory — dma0 injects at (0,1), dma1 injects at (0,2)
Two DMA engines. Each has an AXI4-Lite config slave (CPU programs the transfer via SRC_ADDR / DST_ADDR / LENGTH / CTRL registers) and an AXI4-Lite master port (performs the actual read-then-write transfer). The DMA master port connects to the router inject port at its assigned node. dma0_irq feeds irq_crypto src[4], dma1_irq feeds src[5].
Required internal register names (): the FSM state register must be named dma_st (3-bit; value 0 = idle) and the STATUS/IRQSTAT combined 32-bit register must be named r_stat (bit 0 = busy, bit 1 = done).
10

IRQ Aggregators

dual 8-source aggregators
Two independent 8-source IRQ aggregators. Each outputs cpu_irq (level) and cpu_irq_id[2:0] (lowest active source ID). Unused sources are tied to 0. The aggregator is an APB slave -- its registers are accessible for polarity / mask configuration.
11

Async FIFO Mailbox

CDC -- sys_clk to dsp_clk
An async_fifo bridges the CPU clock domain (write side) to the DSP clock domain (read side). The CPU pushes words by writing to SoC config register offset 0x00 (MBOX_DATA). The DSP clock domain reads via the mbox_rd_en port of the top module. The mbox_empty flag and mbox_level[3:0] occupancy counter are available on the CPU side via config reg offset 0x04.
12

Performance Counter

4 channels x 32-bit
A perf_counter with 4 event channels, each counting positive edges of its event input. Channels are wired as: ch[0] = ni_00 tl_a_valid (NoC transactions from CPU), ch[1] = DMA0 IRQ (completed DMA words), ch[2] = DMA1 IRQ, ch[3] = any AES done (OR of aes0..aes3). Counter values are readable via SoC config registers 0x08..0x14. Enable counting with PERF_CTRL[0]=1. Write PERF_CTRL[1]=1 to clear all counters; this bit self-clears the next cycle.
13

Address Map

memory map
The TileLink router uses the top 8 bits of the 32-bit address for XY routing. The crossbar decodes the top nibble (addr[31:28]) to select NoC, APB, or SoC config space: any address where addr[31:28] != 4'hF goes to the NoC (S0); addr[31:28]==4'hF0 (i.e., 0xF000_xxxx) goes to the APB cluster (S1); addr[31:28]==4'hF0 and the next nibble selects 0xF001_xxxx for SoC cfg (S2). In other words, route to S0 if addr[31:28] != 0xF, S1 if addr[15:12]==0x0 within the 0xF000_xxxx range, S2 if within 0xF001_xxxx.
